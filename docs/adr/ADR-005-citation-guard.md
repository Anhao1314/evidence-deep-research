# ADR-005: 引用 Guard 采用 fail-closed 的结论隔离

状态：已采纳（2026-10-29 返工） | 日期：2026-10-28

## 背景

任务硬约束：报告中的结论必须能回到实际检索结果，不允许模型编造脚注。提示词约束只是软约束，必须回答“非法引用发生时系统怎么办”。

上一版把“剥离非法引用、保留结论”称为无损降级，这是错误的：删除 `[E99]` 后，模型结论仍然留在主报告里，读者会把无来源的结论当成已验证研究结论。本轮改为 fail-closed。

## 决策

统一编号体系 + 受控重写 + 结论隔离：

1. **编号体系**：merge 节点对去重后的证据统一分配 `S1..Sn`（来源）与 `E1..En`（证据），子 Agent 内部用空占位 ID；全局唯一性由单一节点保证。
2. **离线模式**：结论句由证据条目模板构造，引用在结构上直接绑定真实证据。
3. **在线模式 Guard**（`app/report/citation_guard.py`）：
   - 保存 Guard 前原始输出、Guard 后最终报告、unified diff；
   - 非法 `[E#]` 先做一次受限重写；
   - 重写必须通过程序校验：**去掉全部 `[E#]` 后，正文必须与原始输出一致**；否则拒绝此次重写；
   - 重写仍非法或重写被拒绝时，把受影响结论移出主报告，写入 `unverified_claims`；
   - 如果一个已验证结论都不剩，回退到基于证据的模板报告；模板也不可用时输出安全占位（fail-closed）；
   - Guard 事件记录原始结论、非法 ID、重写结果、最终动作与被隔离结论。

## 理由

- **不能用“删引用”制造伪验证**：结论无来源仍进入主报告，等于把模型断言伪装成研究结论；
- **程序校验重写**：只靠 prompt 说“禁止修改正文”不可靠，必须比较去引用后的正文；
- **结论级隔离**：按句子/表格单元定位结论，保留能追溯的部分，移除不能追溯的部分；
- **fail-closed**：无法可靠保留已验证结论时，宁可回退到有引用的模板或安全占位，也不展示无引用结论；
- **审计可复核**：原始输出、最终输出、差异、非法 ID、隔离文本都在 Report/GuardAudit 与 Trace 中。

## 边界（诚实声明）

- Guard 只校验“引用编号是否存在于真实证据集合”，**不校验该证据是否在语义上支撑结论**；
- 合法编号不等于事实正确；语义支撑只能由人工标注复核（`eval/annotation.py`：supported/partial/unsupported/cannot_judge）；
- 本仓库不使用 LLM Judge 的分数冒充人工事实正确率；未标注时统一 `NOT_MEASURED`；
- Guard 会移除无法追溯的结论，因此最终报告可能比模型原始输出短，甚至只能回退到模板；这是有意的 fail-closed，不是“无损”；
- 系统只能保证不存在的证据编号不会继续作为有效引用展示，**不能保证**所有展示出来的引用都语义正确。

## 后果

+ 无来源/非法编号的模型结论不会继续留在主报告；
+ 原始输出与隔离结论可审计，便于分析模型引用行为；
− 报告可能缺少部分结论，或在极端情况下回退到模板/安全占位；
− Guard 不能替代事实核查与人工语义复核。
