# ADR-005: 引用强制靠后处理 guard，不靠提示词自觉

状态：已采纳 | 日期：2026-10-28

## 背景

任务硬约束：报告中每个结论的引用必须来自实际检索结果，不允许模型编造脚注。LLM 的提示词约束是软约束，必须回答"非法引用发生时系统怎么办"。

## 决策

统一编号体系 + 分级 guard：

1. **编号体系**：merge 节点对去重后的证据统一分配 `S1..Sn`（来源）与 `E1..En`（证据），子 Agent 内部用空占位 ID——全局唯一性由单一节点保证，避免并行实例冲突；
2. **离线模式**：结论句直接由证据条目模板构造，引用在结构上不可能编造；
3. **在线模式 guard**（`app/report/citation_guard.py`）：非法 [E#] → 受限重写一次（只允许修正引用，禁止改写其他文字）→ 二次仍非法 → **剥离**非法标记并落 `error` 事件。

## 理由

- **宁可无引用，不可假引用**：剥离是无损降级（结论还在，只是失去标注）；假引用是信任崩塌（用户无法分辨真假）；
- **受限重写一次**：给模型自纠的机会（多数情况是编号幻觉而非结论错误），但不无限重试（成本与延迟）；
- **guard 判定是纯函数**：`check_citations` / `strip_invalid_citations` / `extract_citations` 独立于 Provider，pytest 直接覆盖三条路径（合法通过/重写修复/剥离告警）；
- **评测同源**：`no_fabricated_citations` 断言消费同一编号体系，引用不达标即 CI 红。

## 边界（诚实声明）

guard 校验"引用编号是否存在于真实证据集合"，不校验"该证据是否真的支撑这句话"——后者是语义级问题，属于外部评测框架中 LLM-as-judge 的职责（eval 的断言接口为此保留了 evidence 明细）。

## 后果

+ 编造引用在系统层面不可能到达用户；
− 剥离路径会让个别结论暂时失去标注（trace 可审计，报告"信息缺口"节可见）。
