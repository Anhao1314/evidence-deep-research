# ADR-004: 跨会话记忆的三表划分与召回策略

状态：已采纳 | 日期：2026-10-28

## 背景

系统需要跨会话记忆（用户偏好、历史研究、结论沉淀）。关键问题：什么进长期记忆、怎么组织、何时召回、何时写入。

## 决策

**划分原则：短期记忆 = LangGraph State（run 生命周期终点即消失）；长期记忆 = SQLite 三表，只进结构化、可再利用的信息。**

| 表 | 内容 | 召回方式 |
|---|---|---|
| `user_preferences` | 报告语言、证据预算等偏好 | 全量注入 |
| `research_topics` | 历史研究问题 + 结论摘要 | BM25 相似度 top-k |
| `knowledge_snippets` | 每维度最高分证据的 claim（挂 topic 下） | 按召回主题关联取回 |

写入时机：`persist` 节点（报告落定后）——只沉淀**已完成且有证据支撑**的研究；召回时机：`load_context` 节点——偏好进入合成上下文、历史主题进入 Planner 的提示词/rationale。

## 理由

- **不存原始对话**：对话历史无法被新 run 直接再利用，是负债不是资产；结构化 claim + source_refs 才能直接注入新研究；
- **偏好必须真实生效**：`report_language` 切换报告语言（双语模板）、`max_evidences_per_object` 收紧 merge 预算——记忆如果只是"存了"而没有可观察的行为影响，就是演示摆设；
- **召回用 BM25 而非 embedding**：与 ADR-003 同构——主题数量小、离线可跑、确定性可测；
- **沉淀粒度是"每对象每维度一条"**：报告 evidences 已按相关度排序，取每组首个即可，不需要额外的摘要模型调用。

## 后果

+ 记忆闭环在离线模式完整可测（跨会话持久化有专项测试）；
+ `GET /api/memory/{user_id}` 提供外部可观测入口；
− 结论沉淀是抽取式的（最高分证据的 claim），不做跨主题的知识融合——这是"研究结论沉淀"而非"知识图谱"的定位。
